# Blend

Blend is a private two-person YouTube taste comparison. Each participant connects their own Google account, reviews the data-sharing notice, and grants read-only access. Blend turns subscriptions, liked or saved videos, and playlists into a guided shared reveal.

Blend does not access watch history and does not change either YouTube account. Compatibility scores, interest labels, and recommendations are generated by Blend and are not YouTube or Google metrics.

## Product flow

1. The host connects Google and prepares a current YouTube snapshot.
2. Blend creates a single-use invitation that expires after two hours.
3. The guest reviews the exact sharing boundary and connects separately.
4. Both participants can view the same five-part reveal: signal, shared finds, recommendations, interest shape, and a shareable summary.
5. Account settings provide local sign-out, Google disconnection, and permanent account-data deletion.

## Stack

- React, TypeScript, Vite, Tailwind CSS, and Framer Motion
- FastAPI and MongoDB
- Google OAuth 2.0 and YouTube Data API v3
- Vercel deployment

## Local development

The frontend requires `VITE_API_URL`. The backend requires MongoDB, Google OAuth, and JWT environment values documented in `backend/.env.example`.

```bash
cd frontend
npm install
npm run dev
```

```bash
cd backend
python -m pip install -r requirements.txt
uvicorn main:app --reload
```

## Security and data lifecycle

OAuth handoff codes are single-use and expire after two minutes. App access tokens are short-lived; refresh tokens are random, hashed in storage, and rotated when used. Invitation links expire after two hours. Google credentials and cached API data are stored server-side, not embedded in comparison links. Users can revoke Google access or delete their stored account data from Settings.
